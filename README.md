# ПРЕДЕЛ — прогноз нагрузки жилой застройки на инфраструктуру района

Прототип по задаче МБУ «Центр городской трансформации» (Мэрия Казани), хакатон «Школа цифровых чемпионов 2026».
Размещает проектируемый ЖК в 3D-модели района, прогнозирует население по годам и нагрузку на детские сады, школы,
дороги, общественный транспорт, парковки, торговлю, здравоохранение и инженерные сети. Сравнивает три состояния —
**без ЖК**, **с ЖК**, **с ЖК и мероприятиями** — и формирует перечень мероприятий со сроком, приоритетом, основанием
и стоимостью. Каждая цифра — с формулой, источником, статусом и диапазоном неопределённости.

## Из чего состоит

| Часть | Где | Что показывает |
|---|---|---|
| **Графики** | `public/dash/dash.html` → `/dash/dash.html` | Казань и 7 районов: ученики и дети в садах, факт 2020–2026 и прогноз до 2030, места и нехватка мест, проверка на истории, школы, сады, стройки, застройщики |
| **Как считаем** | `public/dash/formula.html` → `/dash/formula.html` | формула по шагам на цифрах выбранного района и проверка на истории |
| **Калькулятор дома** | `public/dash/calc.html` → `/dash/calc.html` | сколько школьников и детей в саду даст новый дом по годам: квартиры × заселение × школьников на квартиру района × волна |
| **3D: гимназия № 107** | `src/`, `/?view=107` | кварталы 68–69, закреплённые дома, ученики 2021–2026 против мест и прогноза |
| **Новый ЖК** | `src/`, `/?view=empty` | ЖК по очередям на пустой территории: как заселяется и чего не хватает в радиусе 500 м |
| Данные | `pipeline/` (Python), `scripts/` | сбор открытых данных, модель, проверка на истории → JSON в `public/` ([pipeline/README.md](pipeline/README.md)) |

Страницы «Графики», «Как считаем» и калькулятор — статический HTML на готовых JSON (`public/dash/*.json`), 3D-часть —
React + MapLibre с расчётным ядром `src/model`. Сервер не нужен: всё открывается с одного адреса и работает без интернета.

Методика и источники каждого коэффициента — [docs/МЕТОДИКА.md](docs/МЕТОДИКА.md).
Бэклог адаптации, схема интеграции и программа пилота — [docs/ПИЛОТ.md](docs/ПИЛОТ.md).

## Запуск

Нужен Node.js 20+. Интернет не нужен: район, шрифты и глифы карты лежат в `public/`.

```bash
npm install
npm run dev      # http://localhost:5173 — Графики: /dash/dash.html, 3D: /?view=107, Новый ЖК: /?view=empty
npm test         # 41 проверка: пример из ТЗ, нормативы, стресс-тесты, загрузка данных, проверка на построенных ЖК
npm run build    # статическая сборка в dist/ — открывается любым веб-сервером
```

Пересобрать данные района (Python 3.10+, без сторонних библиотек; нужен интернет):

```bash
python scripts/build_district.py --cache <папка кэша> --registry "<путь к БАЗА_ОБРАЗОВАТЕЛЬНЫХ_ОРГАНИЗАЦИЙ_РОССИИ.zip>"
```

Другой район Казани — границы, районы edu.tatar.ru и участок ЖК по умолчанию (так собран Ново-Савиновский, ~2 мин):

```bash
python scripts/build_district.py --bbox 55.800,49.080,55.845,49.170 --edu nsav --site 49.1426,55.813 --name "Казань: Ново-Савиновский район (открытые данные)" --out public/data/kazan-nsav.json
```

## Что умеет

- 3D-модель района Казани из открытых данных (OSM, реестр Рособрнадзора, edu.tatar.ru) и контрольный синтетический район;
- размещение участка кликом, корпуса ЖК поэтажно по очередям, рост по шкале времени 2026–2036;
- школы, сады, перекрёстки — «колбы»: высота колбы — мощность, заливка — загрузка, перелив — перегрузка;
- зоны нормативной доступности, потоки машин от выездов, карточка объекта «без ЖК → с ЖК → с мероприятиями» с источниками;
- норматив МНГП и сценарный расчёт раздельно; диапазон P10–P90 (Монте-Карло), торнадо чувствительности, уверенность у каждого показателя;
- самопроверка во вкладке «Данные»: пример из ТЗ (по нему откалиброваны доли детей и поездки) и стресс-тест с отметками ✓;
- мировая линейка: тот же ЖК по 10 методикам из 6 стран;
- ползунки коэффициента заселения, автомобилизации, возрастной структуры, темпа заселения; пресеты демографии;
- мероприятия со сроком, приоритетом, основанием и стоимостью; включение в сценарий одним щелчком;
- загрузка данных района (JSON, GeoJSON, CSV; виды и колонки — латиницей или по-русски) с проверкой; таблица мощностей и контингента поверх 3D-района уточняет объекты, не стирая застройку; загрузка проекта ЖК и сохранённого сценария; выгрузка результата в GeoJSON;
- отчёт PDF (печать): параметры, прогноз по горизонтам 1/3/5/10 лет, мероприятия, коэффициенты, ограничения;
- режим «Показ» для презентации.

## Перечень признаков (входные параметры)

**Проект** (`Project`): границы участка; корпуса — пятно, этажность, очередь; очереди — год ввода, число квартир,
общая площадь квартир; жители по проекту (необязательно); выезды — координаты, доля потока, полосы; места в саду и
школе ЖК с годом открытия; торговая площадь; машино-места; тип плит.

**Сценарий** (`Scenario`): базовый год; горизонт; темп заселения; коэффициенты (`coefficients.ts`); волна заселения;
динамика района по когортам рождений; стеснённая застройка; число прогонов Монте-Карло и seed.

**Район** (`District`): объекты `kind` = `kindergarten | school | shop | pharmacy | stop | parking | intersection | clinic | sport | metro`,
`name`, `coords` [долгота, широта], `capacity`, `load`, `capacityRange`, `openYear`; единицы: места (сад, школа),
м² (магазин), пасс./ч (остановка), машино-места, авт./ч (перекрёсток).

## Формат загрузки данных района

- JSON: `{ "name": "...", "dataDate": "2026-10-01", "objects": [ { "id", "kind", "name", "coords": [lon, lat], "capacity", "load", "openYear" } ] }`;
- GeoJSON `FeatureCollection` с точками или полигонами (берётся центр) и теми же свойствами;
- CSV с колонками `kind;name;lon;lat;capacity;load` (разделитель `;` или `,`).

При загрузке проверяются вид объекта, координаты, числа, повторяющиеся id; сводка — во вкладке «Данные».
Файл без зданий поверх района с 3D-застройкой уточняет объекты: совпадение по `id` или по виду в 150 м, значения из файла
становятся фактом, оценочный диапазон снимается. Пример — `samples/ПРИМЕР-мощности-ЦГТ.csv` (демонстрационные значения).
JSON с полями `phases` и `site` загружается как проект ЖК.

## Ограничения

Предварительная оценка: не заменяет документацию по планировке территории, транспортное моделирование и инженерные
изыскания. Прогноз по городу и районам на «Графиках» проверен на истории (город — из 2015 года, Ново-Савиновский район — из 2021);
расчёт экрана «Новый ЖК» — сценарный и так подписан. Открытого реестра проектной мощности школ и садов
Казани нет — на реальных данных она оценивается по площади зданий (центр — среднее по школам с опубликованной мощностью) с диапазоном; дефицит в этом случае — верхняя
оценка до получения данных управления образования. В MVP базовый год 2026 и горизонт 10 лет фиксированы; по дорогам
считаются загрузка узлов и выездов и задержка, без длины очередей и загрузки перегонов улиц. Персональные данные не используются.

Что известно и будет закрыто в пилоте:

- **Две модели нового дома.** «Графики» и калькулятор считают детей из новостроек с волной по годам жизни дома
  (форма — калькулятор FolgekostenSchätzer, Бранденбург; уровень — по району Казани). Экран «Новый ЖК» — постоянными долями
  детей из примера ТЗ (10% — 0–6 лет, 14% — 7–17 лет), чтобы сверять расчёт с примером. Объединим в одну модель.
- **Волна не откалибрована на Казани** — проверим на трёх ЖК, сданных в 2018–2022.
- **Места в школах и садах:** точно — у 17 новых школ, у остальных — оценка по площади здания; на страницах подписано «места — оценка».
  Заменит таблица управления образования.
- **Проверка на построенных ЖК Азино** (`src/model/retro.test.ts`): модель «Нового ЖК» ошибается на ~20% по сумме новых ЖК,
  цель пилота — ±15%.
- Дороги и автобусы на экране «Новый ЖК» — синтетический район, не данные Казани.
- Скрипты `pipeline/` работают из своих рабочих папок (пути в начале файлов) — см. [pipeline/README.md](pipeline/README.md).
